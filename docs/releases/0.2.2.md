# Codex Process Jobs 0.2.2

Version 0.2.2 hardens lifecycle routing around wrapped and detached workloads
and adds diagnostics for duplicate CPJ providers.

## User-visible changes

- Codex now classifies the underlying workload rather than the latency of a
  quick wrapper or launcher when deciding whether CPJ applies.
- A task workflow that emits a detached launcher must route the real foreground
  payload through CPJ or use a launcher mode that waits for completion. CPJ
  will not track a wrapper that exits while the actual workload escapes its
  lifecycle.
- Installer preview and `doctor` report distinct CPJ provider caches and warn
  when side-by-side personal and OpenAI-directory copies could make skill
  routing nondeterministic.

## Compatibility and security

There is no persisted-job schema change. CPJ continues to support macOS and
Linux with Node.js 18 or newer. The release does not add a hook or relax
process-output, prompt-injection, symlink, cancellation, or consent boundaries.

The OpenAI Plugins Directory archive is now built from a deterministic,
reviewed allowlist, and the source manifest uses the accepted `Developer Tools`
category.

## Upgrade

Homebrew users must upgrade the management command and then apply the plugin
snapshot update. After every applied update, restart or reload Codex clients,
review `/hooks`, and begin a fresh task. Open tasks may continue using their
preserved older cache generation.

Do not install the personal/Homebrew and OpenAI-directory copies side by side.
