# Codex Process Jobs 0.2.3

Version 0.2.3 adds best-effort live completion delivery to the owning Codex
VS Code task, so a finished detached job can appear in the already-open panel
without a reload, reopened task, or user prompt.

## User-visible changes

- On supported macOS and Linux clients, CPJ can use Codex's guarded private
  same-user IPC transport to deliver a sanitized completion turn through the
  owning VS Code extension session.
- Default `auto` completion mode gives VS Code the same bounded proactive
  result inspection used by Codex App: Codex summarizes the saved result,
  recommends one next step, and asks whether the user wants to proceed.
- Launch messages now describe the actual selected transport instead of
  implying that every client has identical live-delivery behavior.

## Reliability and security

The live relay is experimental and best-effort. Durable job state and later
`status` or `result` retrieval remain authoritative if a client does not render
the completion.

Private IPC is restricted to a validated same-user local socket. If delivery is
rejected before acceptance, CPJ may use another supported relay. If the
connection becomes uncertain after dispatch, CPJ fails closed and does not send
a competing duplicate turn. Automatic completion notices still contain no
process output, command arguments, labels, paths, or environment data.

There is no persisted-job schema migration. CPJ continues to support macOS and
Linux with Node.js 18 or newer.

## Upgrade

The OpenAI Plugins Directory is the supported installation and update surface.
Use its update action, then restart Codex App and CLI, reload VS Code, review
`/hooks`, and open a fresh task. Existing tasks may retain the older cached
plugin generation.

Run exactly one active CPJ provider. Maintainers using the side-by-side local
development setup must reconfirm after the update that the directory provider's
five skills and three hooks remain disabled.
