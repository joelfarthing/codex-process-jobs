# Codex Process Jobs 0.2.5

Version 0.2.5 improves completion pickup for ordinary Codex CLI/TUI sessions
without requiring a daemon, wrapper command, or unfamiliar way to launch
Codex.

## User-visible changes

- CLI-owned jobs now default to one best-effort desktop completion notice when
  the user has not set an explicit notification preference. The default notice
  contains only the job ID, terminal status, and exit code.
- On the first eligible CLI prompt after a job finishes, Codex receives the
  bounded saved-result inspection contract used by the graphical clients:
  inspect with `result --peek`, summarize the outcome, recommend one next
  step, and ask before taking that step.
- `config --notify-user default` clears an earlier durable preference and
  restores the surface default.
- A sandbox-escalated CLI launch retains its CLI classification through the
  owning rollout's exact `source: cli` and `originator: codex-tui` metadata
  when the originator environment variable is unavailable.

## Reliability and security

- A state-directory `EPERM` or `EACCES` failure now directs Codex to rerun the
  identical controller command with scoped or escalated permission instead of
  substituting a different state root.
- Surface-defaulted desktop notices never include job labels or
  command-derived text. A label is eligible only when notification was
  explicitly enabled and the job name was explicitly supplied.
- Any explicit notification opt-out remains authoritative. Non-CLI surfaces
  retain their existing defaults.
- The forensics helper now searches every `process-jobs*` state root under
  `CODEX_HOME`, including the isolated maintainer development provider.

There is no persisted-job schema migration. CPJ continues to support macOS and
Linux with Node.js 18 or newer.

## Known CLI boundary

An already-open Codex TUI still cannot render CPJ's synthetic completion turn
spontaneously. The desktop notice tells the user that the job finished, and
the first later eligible prompt picks up and interprets the result. On Linux,
the optional desktop notice requires a graphical notification environment and
`notify-send`; durable next-turn pickup remains available without it.

## Upgrade

Use the OpenAI Plugins Directory update action, then restart Codex App and CLI,
reload VS Code, review `/hooks`, and open a fresh task. Existing tasks may
retain an older preserved cache generation.

Run exactly one active CPJ provider. Maintainers testing the isolated
`codex-process-jobs-dev` provider must keep all directory-provider CPJ skills
and hooks disabled during the test.
