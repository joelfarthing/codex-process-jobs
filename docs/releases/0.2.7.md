# Codex Process Jobs 0.2.7

Version 0.2.7 adds explicit, safety-checked reruns for finished jobs and makes
CPJ's model-facing workflow rely only on the current request and validated CPJ
state.

## User-visible changes

- A finished job can be launched again with the new `rerun` skill or
  `job.mjs rerun JOB_ID` controller command.
- Every rerun creates a new tracked job and log set while retaining `rerunOf`
  lineage back to the source job.
- CPJ preserves the validated argv, working directory, execution mode,
  critical classification, and explicit name from the source record.
- Rerun launches follow the same hard turn-release boundary as ordinary CPJ
  starts: Codex reports the new job ID and does not monitor it in that turn.
- Completion pickup presents shorter, user-legible hook context while retaining
  bounded result inspection and the permission boundary before follow-up work.
- All six operational skills now explicitly skip memory lookup for CPJ work.
  The current request and validated CPJ state remain authoritative.

## Safety and compatibility

Reruns are never automatic. Codex must receive an explicit user request or
approval for a specific finished job. The controller refuses active jobs,
requires `--force` for critical jobs, and fails closed for incomplete
invocations, missing working directories, or legacy shell records whose
historical interpreter contract cannot be reproduced safely.

Existing persisted jobs remain readable. Eligible schema-v2 jobs can be rerun;
older or incomplete records remain available for status and result inspection
but are not treated as executable rerun recipes.

CPJ continues to support macOS and Linux with Node.js 18 or newer. Automatic
conversational wake remains best-effort and depends on experimental Codex
client behavior.

## Upgrade

Use the OpenAI Plugins Directory update action, then restart Codex App and CLI,
reload VS Code, review `/hooks`, and open a fresh task. Existing tasks may
retain the older cached plugin generation.

Run exactly one active CPJ provider. Maintainers testing the isolated
`codex-process-jobs-dev` provider must keep all directory-provider CPJ skills
and hooks disabled, then re-confirm those toggles after every directory update.
