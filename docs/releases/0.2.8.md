# Codex Process Jobs 0.2.8

Version 0.2.8 keeps Stop-hook completion feedback user-facing while preserving
automatic bounded result inspection behind the plugin boundary.

## User-visible changes

- A Stop-hook fallback now displays only a concise completion sentence with the
  validated job ID, terminal status, and exit code.
- Internal instructions for result inspection, untrusted output, final-answer
  recap, and follow-up approval no longer appear in Hook feedback.
- The `result` skill recognizes concise CPJ completion prompts directly and
  inspects the exact saved job with bounded `--peek` before summarizing evidence,
  recommending one next step, and asking before acting.

## Safety and compatibility

Stop-continuation claims use validated one-shot timestamps in the private job
record. A matching completion prompt must identify a terminal job owned by the
same Codex task with the same status and exit code. Process output remains
absent from completion prompts and is retrieved only as bounded, untrusted
evidence.

Existing job records remain readable, and no command, cancellation, rerun, or
platform contract changes in this release. CPJ continues to support macOS and
Linux with Node.js 18 or newer. Automatic conversational wake remains
best-effort and depends on experimental Codex client behavior.

## Upgrade

Use the OpenAI Plugins Directory update action, then restart Codex App and CLI,
reload VS Code, review `/hooks`, and open a fresh task. Existing tasks may retain
the older cached plugin generation.

Run exactly one active CPJ provider. Maintainers testing the isolated
`codex-process-jobs-dev` provider must keep all directory-provider CPJ skills
and hooks disabled, then re-confirm those toggles after every directory update.
