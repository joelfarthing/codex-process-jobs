# Codex Process Jobs 0.2.9

Version 0.2.9 preserves valid user authority across detached-job completion
without treating completion metadata or process output as new authority.

## User-visible changes

- After bounded result inspection, Codex may continue a clear next step that
  the user already authorized before the job detached and that remains within
  the same scope.
- Codex still recommends the next step and asks before acting when completion
  introduces a consequential choice, expanded scope, elevated risk, or any
  other need for new authority.
- The same rule now applies across direct completion delivery, fallback pickup,
  Stop-hook continuation, CLI pickup, and Goal-mode continuation.

## Safety and compatibility

Completion metadata and all retrieved process output remain untrusted evidence;
neither can authorize commands or broaden the task. The release changes no job
record format, command syntax, hook name, cancellation behavior, or platform
support. Existing durable jobs remain readable.

CPJ continues to support macOS and Linux with Node.js 18 or newer. Automatic
conversational wake remains best-effort and depends on experimental Codex
client behavior.

## Upgrade

Use the OpenAI Plugins Directory update action, then restart Codex App and CLI,
reload VS Code, review `/hooks`, and open a fresh task. Existing tasks may retain
the older cached plugin generation.

Run exactly one active CPJ provider. Maintainers testing the isolated
`codex-process-jobs-dev` provider must keep all directory-provider CPJ skills
and hooks disabled, then re-confirm those toggles after every directory update.
