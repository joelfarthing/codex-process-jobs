# Codex Process Jobs 0.3.0

Version 0.3.0 adds explicit-opt-in live completion delivery for ordinary Codex
CLI/TUI sessions through Codex's official shared local App Server.

## User-visible changes

- A CLI-owned detached job can now wake its already-open ordinary `codex` TUI,
  render the sanitized completion notice, and run the same bounded proactive
  result inspection used by Codex App and VS Code.
- A matching completed live CLI turn suppresses the later ordinary-prompt
  recap, so the next unrelated question is answered without repeating the job
  completion.
- The feature remains off by default. The existing daemon-free OS notification
  and one-time next-turn pickup remain unchanged and authoritative when live
  delivery is unavailable.
- Maintainers can install an isolated `codex-process-jobs-dev` provider whose
  skills, hooks, state, and cache identity can be toggled independently of the
  Marketplace provider.

## Compatibility and setup boundary

Live CLI delivery requires an active Codex installation that can run
`codex app-server daemon start` before the ordinary TUI starts. The
npm-distributed Codex CLI 0.147.0 tested for this release could not start that
managed daemon without a separate managed standalone Codex installation. CPJ
does not install another Codex distribution, modify `PATH`, or start a daemon
automatically. Users whose active installation does not already support the
managed daemon should leave live CLI injection disabled and keep the normal
daemon-free fallback.

The end-to-end macOS acceptance test used an isolated foreground App Server to
exercise the same socket protocol without changing the host's Codex
installation. A 75-second detached job released its assigning TUI turn, woke
the idle TUI at completion, produced a successful bounded summary, and did not
repeat the completion when the next unrelated prompt was submitted.

## Security

The new transport accepts only the validated owning CLI thread and a sanitized
completion sentence. It requires a real same-user Unix socket and parent
directory inaccessible to group and other users, bounds WebSocket handshake,
frame, and message parsing, rechecks that the thread is idle immediately before
dispatch, and falls back only before possible turn acceptance. It never sends
command text, paths, environment, labels, stdout, or stderr through the
completion notice.

## Upgrade

Use the OpenAI Plugins Directory update action, restart Codex App and CLI,
reload VS Code, review `/hooks`, and open a fresh task. Existing tasks may retain
the older cached plugin generation.

Live CLI delivery remains experimental and disabled by default. Enable it only
after confirming the active Codex installation already supports the managed
local App Server daemon. Codex is a moving target; retain the daemon-free
fallback when this private integration changes or is unavailable.
