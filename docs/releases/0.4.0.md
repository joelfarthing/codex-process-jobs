# Codex Process Jobs 0.4.0

Version 0.4.0 makes live completion delivery zero-setup in Codex CLI 0.149.0
and newer, fixes completion delivery when a Codex task retains an active
writer, and gives the visible workflow a restrained CPJ identity.

## User-visible changes

- An ordinary `codex` TUI can now wake when its detached job finishes without
  a daemon, wrapper, special invocation, or CPJ preference. CPJ sends the
  sanitized completion through the official `codex queue` command for the
  exact owning task.
- Codex owns ordering behind a legitimate or stale active writer. CPJ no longer
  retries the same resume request while guessing when the client is idle.
- Launch commentary names **Codex Process Jobs** instead of a generic detached
  skill or workflow.
- New visible completion turns begin `CPJ background job`, while existing
  in-flight jobs using the earlier unbranded grammar remain valid.
- The trusted completion hook performs the same bounded proactive result
  inspection in queue-woken CLI tasks as in Codex App and VS Code, then marks
  the queued notice consumed so the next unrelated prompt does not repeat it.

## Compatibility

Official queue delivery requires Codex CLI 0.149.0 or newer. Older or
incompatible Codex builds safely fall through to CPJ's existing private IPC,
portable App Server, and one-time hook pickup paths. Durable status, tail, and
result remain authoritative on every supported version.

The earlier shared-App-Server CLI experiment remains available only as a
legacy fallback. It is no longer ordinary setup and CPJ never installs or
starts its daemon.

## Security and reliability

- The queue process receives only a validated owning task ID and sanitized
  terminal sentence as fixed argv with `shell: false`.
- Queue stdout, stderr, and acknowledgment time are bounded.
- A missing or unsupported queue command may fall back, but timeout, signal,
  or output overflow is treated as acceptance-uncertain so CPJ never risks a
  duplicate completion through another transport.
- The hook verifies the visible job ID, status, and exit code against private
  same-task persisted state before supplying hidden result policy.
- The complete release suite passes 231/231 tests, including exactly-once
  queueing, stale-writer handling, legacy grammar compatibility, proactive
  inspection, and next-turn duplicate suppression.

## Upgrade

Use the OpenAI Plugins Directory update action, restart Codex App and CLI,
reload VS Code, review all three CPJ definitions and referenced source through
`/hooks`, and open a fresh task. Verify that only one CPJ provider is active.
Existing tasks may retain their older cached plugin generation by design.

Automatic conversational wake remains best-effort because Codex is a moving
target. The detached job record and bounded result remain available even when
a client cannot render the live completion.
