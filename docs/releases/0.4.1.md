# Codex Process Jobs 0.4.1

Version 0.4.1 makes first-use behavior consistent between local development and OpenAI Plugins Directory installations. A new consent-gated hook helps Codex recognize qualifying local workloads without requiring the optional `AGENTS.md` policy.

## User-visible changes

- Codex now pauses before a non-obviously-short local command and classifies the underlying workload. Long downloads, inference programs, project-specific scripts, builds, tests, benchmarks, data jobs, and repairs can enter Codex Process Jobs even when their executable names are unfamiliar.
- Clearly quick commands, interactive programs, persistent services, already-detached commands, and CPJ controller commands continue normally.
- A successful CPJ start is a hard release boundary. Codex reports the job ID, says that a completion notification should appear, and ends the assigning turn instead of waiting or polling.
- Launch reports no longer expose controller mechanics or internal procedure.
- Completion summaries stay focused on the underlying workload. They do not offer generic CPJ actions or another test when no task-level next step exists.

## Parent-owned execution

The visible parent task now owns every local CPJ launch. If a request asks a subagent to run a qualifying local process, the parent handles the launch instead. The process is not delegated, and the parent does not wait for a child lifecycle after detachment.

This boundary prevents a delegated build, download, inference run, or benchmark from holding the parent turn open while CPJ tracks the same work in the background.

## Compatibility

The new adoption hook requires explicit trust through Codex `/hooks`. The existing optional `AGENTS.md` policy remains available as a routing preference, but Marketplace users do not need it for CPJ to recognize qualifying workloads.

Codex App, the VS Code extension, and Codex CLI/TUI 0.149.0 were tested with the same isolated-subagent proof. On all three surfaces, the parent launched the script once, released the assigning turn, received the completion, inspected the bounded result, and did not delegate or rerun the process.

## Security and reliability

- The foreground classifier does not execute or rewrite the candidate command. It fails open on malformed or oversized hook input.
- The hook injects fixed policy from bounded prompt text and validated task metadata. It does not insert matched user text or process output into hidden policy.
- A spawned subagent cannot own a qualifying process, call CPJ `start` or `rerun`, or use the foreground escape to bypass the parent boundary.
- The production and development packages now use one reviewed runtime-file manifest. A parity test permits only the expected development identity, cachebuster, display text, state namespace, and generated marker differences.

## Upgrade

Use the OpenAI Plugins Directory update action. Restart Codex App and CLI, reload VS Code, and review all four CPJ definitions through `/hooks`. Open a fresh task and verify that only one CPJ provider is active.

Automatic conversational wake remains best-effort because Codex is a moving target. Durable job state and bounded result retrieval remain authoritative when a client does not render a live completion.
